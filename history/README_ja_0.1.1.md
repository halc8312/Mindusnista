# Mindustry → Pythonista 移植開発版 0.1.1

**目標は、ゲーム本体を Python へ移植して iPhone の Pythonista 内で編集・実行すること。**
この配布物は、そのための最初の実装です。完成した完全移植ではありません。
コンベア・乾式ドリルの計算の一部を原作ソースから移し、暫定のワールド・戦闘・保存・描画で結びました。
WebView、JavaScript 版の埋め込み、遠隔操作、JVM の呼び出しは使っていません。

基準：Mindustry **v159.7**。作成日：**2026-09-09**。非公式プロジェクトです。

初期化完了前の更新・保存を防ぎ、最初の起動エラーを記録するように変更しました。

## 1. iPhone で起動

1. `mindustry_pythonista.py` を Pythonista 本体のスクリプト用フォルダーに取り込みます。
2. Pythonista 本体のエディタでそのファイルを開き、実行ボタン ▶ を押します。
3. 操作説明が出たら「ゲームへ」を押します。初期状態では工場が2系統、設置済みです。

必要な実行ファイルは **この .py 1個**です。追加パッケージのインストールや原作アセットのダウンロードは不要です。
標準ライブラリと Pythonista の `scene` / `ui` を使います。アプリ本体で実行してください。
PC 上で通常実行すると GUI は開かず、Pythonista が必要であることを表示します。

**実機の Pythonista/iOS では未検証です。** この配布で確認できたのは CPython 上のシミュレーション、抽出した Java 計算部との比較、模擬 `scene` / `ui` による画面側の Python 処理です。
Apple の描画、フォント、実タッチイベント、実機 FPS、メモリー使用量の確認は含みません。

## 2. 入っているもの

- 48 × 32 タイルの独自デモマップ。原作キャンペーンのマップではありません。
- コア、2 × 2 機械式ドリル、コンベア、ルーター、デュオ、銅の壁。
- 銅・鉛の採掘、向きと間隔のあるコンベア輸送、分配、銅弾薬の補給。
- 暫定の敵、経路探索、ウェーブ、射撃、弾の連続区間での当たり判定、コア破壊。
- 建築費、50% の撤去返却、タッチ操作、カメラ移動、拡大縮小、一時停止、2倍速。
- JSON による独自形式の手動保存・自動保存・再開。原作の `.msav` / `.msch` とは非互換です。
- 数値を変更できる任意の `content_overrides.json` と、直接編集できる Python ソース。

既存の Java / JavaScript MOD、ネットワーク、研究・キャンペーン、液体・電力・製造設備、原作ユニット、原作の画像・音声は **未実装**です。
詳細は `PORT_STATUS.md` を参照してください。

## 3. 最初の動作確認

左側の銅鉱床にあるドリルからコンベアを通ってコアへ銅が入ります。起動直後はドリルのウォームアップと輸送のため少し間があります。
中央上のもう一つのドリルは、ルーターを経由して2つのデュオに銅を配ります。デュオには初期弾薬も入っています。

初期コア資源は銅500・鉛150、配置済み設備はデモ用として無料設置済みです。
「ウェーブ」で敵を出せます。敵の入口はマップ右側です。「移動/調査」で右へ画面を移動すると戦闘が見やすくなります。
通常モードでは最初の自動ウェーブまでシミュレーション時間で90秒あります。メニューを開いている間はシミュレーションが止まります。

## 4. 操作

| 操作 | 内容 |
|---|---|
| 移動/調査 | 1本指ドラッグで画面移動。建物をタップするとHPや内容を表示します。 |
| 2本指 | ズームと画面移動。最初から2本指で始めれば建築しません。 |
| ドリル / ベルト / 分配器 / デュオ / 銅の壁 | 選んで地面をタップすると建築。ドリルは銅色か紫色の鉱床に置きます。 |
| ベルト・銅の壁 | 1本指ドラッグで連続設置できます。ベルトの向きはドラッグ中も固定です。 |
| 回転 | 新しく置くベルトの向きを変更。「移動/調査」で選択した既存ベルトも回転できます。 |
| 撤去 | タップまたはドラッグで撤去。コアは撤去できません。中のアイテムは回収されません。 |
| 停止 / 再開 | シミュレーションだけを停止・再開。停止中も建築できます。 |
| ×1 / ×2 | シミュレーション速度。実機が追いつかない場合に2倍を保証するものではありません。 |
| ウェーブ | 次の敵群を生成。出現待ちが残る間の連打は無効です。 |
| コアへ | カメラをコアへ戻します。 |
| メニュー | 保存・読込・研究用モード・新規デモ・操作説明。 |

新規デモと手動読込は、ボタンを4秒以内にもう一度押して確定します。
研究用モードは建築を無料にし、自動ウェーブを止めます。既にいる敵や手動ウェーブは止めません。

## 5. 保存と復帰

通常は同じフォルダーの `_mindustry_pythonista/` を使います。
0.1.1では、そこに書き込めないとき `~/Documents/_mindustry_pythonista` を代替先として試します。
切替時は画面とコンソールに通知し、元の保存ファイルは削除も移動もしません。
これはセーブの自動移行ではありません。詳しくは `CHANGES_0.1.1.md` を参照してください。

| ファイル | 内容 |
|---|---|
| `autosave.json` | 画面更新が進んでいる間の約30秒ごと、およびライフサイクルの保存処理で書き込みます。次回起動時に自動読込します。 |
| `manual.json` | メニューの「手動保存」「手動読込」専用です。自動保存はこのファイルを上書きしません。 |
| `before-new.json` | 「新規デモ」に切り替える直前のバックアップです。新規デモを再び作ると更新します。 |
| `crash.log` | 起動・更新・リサイズで捕捉した最初の例外のログ。書込可能な保存先に記録します。ログを書けない場合もコンソールに表示します。全種類のクラッシュを捕捉できるわけではありません。 |
| `unreadable-autosave-*.json` | 起動時に読めなかった自動保存の退避コピーです。元のファイルを消して新規保存で潰す代わりに保持します。 |

一時ファイルに書いてから置換する方式です。ロードは形式・数値・重なり・IDなどを検査した後に、動作中のワールドと入れ替えます。
強制終了・メモリー不足・アプリ停止では、直近の操作が保存されない可能性があります。重要な変更後は手動保存してください。

カメラ位置や選択ツールは保存対象ではありません。セーブには使用中のコンテンツ数値も含めるため、保存後に設定ファイルを変更しても、ロードしたゲームの数値は変わりません。

`before-new.json` を復旧したい場合は、ゲームを停止してから現行 `manual.json` を別名に退避し、`before-new.json` のコピーを `manual.json` にして、起動後に「手動読込」を選びます。

## 6. 改造

### 簡単な数値変更

同じフォルダーに `content_overrides.json` を置いて、例えば次のように書きます。

```json
{
  "duo": {"damage": 18},
  "conveyor": {"speed": 0.08}
}
```

これはデュオのダメージとコンベア速度を変更する例です。「新規デモ」で新しい設定を適用します。
同梱の `content_overrides.example.json` をコピーして名前を変更しても使えます。
変更できるのは既存6種類の対応済みフィールドです。未知のブロック、サイズ・容量の変更は受け付けません。
速度、射程、弾の寿命など相互に関係する値は、一緒に調整する必要があります。

### Python を変更

`World._tick_conveyor()`、`World._tick_drill()`、`World._tick_turret()` がそれぞれの入口です。
実際の描画・操作は `make_scene_class()` の中に分離されています。
シミュレーションの変更は、`scene` / `ui` を読み込まずに PC 側でもテストできます。

追加機能を入れる時は `PORT_STATUS.md` で「移植済み」「暫定」「未着手」を分け、テストを追加してください。
原作の既存MOD互換とは別の、今回の移植版を直接改造する仕組みです。

## 7. 開発テスト

PC の Python で、プロジェクトフォルダーをカレントディレクトリにして実行します。

```sh
python mindustry_pythonista.py --self-test
python -m unittest discover -s tests -v
python mindustry_pythonista.py --benchmark
```

本体だけを Pythonista に取り込んだ場合、別スクリプトから `import mindustry_pythonista; mindustry_pythonista.self_test()` でも組み込みテストを実行できます。

Java 参照データの再生成（PC と JDK がある場合のみ）：

```sh
cd reference
javac ConveyorKernelReference.java
java ConveyorKernelReference > java_fixtures.json
```

この Java は原作ゲーム全体ではありません。元のクラスから切り出し・調整した、コンベアの移動・受入条件と乾式採掘の独立した計算参照です。
コンベアの比較許容差は2e-6、乾式採掘の進捗は0.002です。JavaのfloatとPythonのfloatの精度差があるため、ビット単位一致の主張はしません。

`TEST_REPORT.md` に実際の実行結果、`test-results.txt` にログを収録しています。

## 8. 起動しない場合

- **`No module named scene` / `ui`**：PCや別のPythonアプリではなく、Pythonista本体のエディタで実行しているか確認します。
- **設定ファイルに関するエラー**：`content_overrides.json` を一度別名にして再実行します。無効な設定を黙って無視しない設計です。
- **保存読込のエラー**：保存ファイルを消す前にコピーを作ってください。本家 `.msav` は読めません。
- **画面や操作がおかしい**：機種、iOS/Pythonistaの版、エラー全文を記録します。`crash.log` ができていれば、その内容も確認します。
