## Pythonista で使う

`pythonista_parallel_probe.py` だけを Pythonista に置き、通常の実行ボタンで起動できます。
標準ライブラリだけでも Python 基準経路が動きます。NumPy は実行時に任意で読み込み、
利用できなければ3つの NumPy 条件を「未実行」と記録します。pip は必要としません。
ゲームの `.py` や保存ファイルを同じ場所へ用意する必要はありません。

既定では20,000件・ウォームアップ2回・継続7回で、結果の JSON と日本語要約をコンソールへ出します。
JSON は標準出力、日本語要約は標準エラーです。自動でファイルを作りません。
標準実行でも短時間の計算を行うため、実行中は比較器の処理完了を待ちます。
Pythonista の版・ビルド・iOS版は利用できるアプリ情報から読み、取得できない場合は未取得と残します。
端末のユーザー設定名や保存内容は採取しません。

PC での実行例、または Pythonista へ渡す引数の例:

```sh
python tools/pythonista_parallel_probe.py
python tools/pythonista_parallel_probe.py --count 200000 --repeats 11
python tools/pythonista_parallel_probe.py --no-numpy
python tools/pythonista_parallel_probe.py --output probe-result-01.json
```

`--output` は指定した新規ファイルにだけ書きます。既存パスなら実行前に拒否し、上書きしません。
書き込みの flush / close が完了してから保存先を表示し、その段階の失敗もエラー終了として扱います。
保存を伴う実行が途中で中断・失敗した場合、新規の空ファイルまたは不完全な結果が残ることがあります。
そのファイルを成功証跡にせず、別名で再実行してください。既存のゲーム保存にはアクセスしません。
件数・反復数は明示的に増やせますが、大きい入力の所要時間とメモリはまだ実機未測定です。

## 比較する仕事と精度

固定 seed `1597` から、各行に座標2組と距離二乗の閾値を作ります。
全条件が同じ総件数と同じ入力を処理し、次を求めます。

```text
dx = x - target_x
dy = y - target_y
distance_squared = dx * dx + dy * dy
hit = distance_squared <= threshold_squared
```

原点、等距離、閾値と完全一致、閾値の直前・直後の浮動小数点値、1e-6 / 1 / 1e6 の尺度を含めます。
Python の基準値と NumPy `float64` の距離二乗・真偽マスクを**許容誤差0で全件比較**します。
初回・ウォームアップ・継続の全実行を検査し、一度でも不一致があればその条件は不一致です。
最初の差分位置と値を JSON に残し、速度比による成功表示を付けません。

これは独立した数値演算の比較です。原作 Java の float32、同距離の標的選択、命中順、乱数更新順、
資源収支等を検証したものではありません。原作との許容誤差を今回の結果から決めません。

## ワーカーと時間の扱い

- 入力全体を毎回 NumPy 配列へ変換し、読み取り専用にします。
- 行の範囲を順にほぼ等分し、余りは先頭側へ1件ずつ配ります。重複や欠落はありません。
  件数がワーカー数より少ない場合、空の範囲へ仕事を送らないため実タスク数は少なくなります。
- 各ワーカーが自分の出力配列を持ちます。全範囲の完了を待ち、元の行順で Python のリストへ反映します。
  ワーカーが世界のHP・在庫などを書き換える処理はありません。
- 1ワーカーも同じ `ThreadPoolExecutor` を使います。要求ワーカー数は同時 CPU 実行の実証ではありません。

各回の計測は、**入力変換・割り当て・仕事の配布・同期・Python 結果リストへの反映まで**を含みます。
データ生成・基準値生成・結果照合・レポート生成は別で、速度比の区間には含めません。
NumPy import、executor 準備、初回処理、ウォームアップ、継続処理を分けて記録します。
executor は条件ごとに作り直し、その条件内の継続処理で再利用します。実スレッドの遅延起動は初回時間に入ります。
`first_with_prepare_seconds` は executor 準備と初回処理の合計で、別記の NumPy import 時間は含みません。

継続処理は全サンプル・中央値・p95・最大を記録します。p95 はソート後の nearest-rank 方式なので、
少ない反復では最大値になり、安定した長時間のp95とは扱いません。
Python → NumPy 1 → 2 → 4の固定順で実行するため、実行順・周波数・発熱等の影響は残ります。
同条件で繰り返し実行し、実機の長時間試験は別に行います。

数値バッファの概算は1件57バイト（入力float64×5、作業float64×2、bool×1）です。
Python入力・結果・基準値のオブジェクト、executor、allocator、ランタイムのメモリは含みません。
実プロセスのピークメモリは未測定と明記します。57バイト×件数を総メモリ使用量と読まないでください。
