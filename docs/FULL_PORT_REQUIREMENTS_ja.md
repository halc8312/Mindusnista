# 完全移植の規模・品質・互換要件

更新日: 2026-09-10。ARCH-01: ユーザーの追加要件と一次資料調査を計画へ反映。
ゲーム基準は 0.1.2-dev / Mindustry v159.7。これは要件の確定であり、性能達成の報告ではない。

## 完成時に求めるもの

- 超大規模な工場・マップ・戦闘を対象にする。設備・敵・弾・ロジックを間引いたり、
  ゲーム独自の小さな上限を加えたりして完全移植の達成としない。
- 原作 iOS 版・Steam 版とのセーブ共有を目標に含める。単独ワールドだけでなく、
  キャンペーン・研究・セクター・必要な content/MOD/asset の整合性まで扱う。
- 爆発・弾道・発光・煙等の見た目と情報量を移植の品質要件にする。
  現在の簡易図形を完成品質とはしない。自動で効果を削って性能合格にすることもしない。
- Pythonista 向け Python 本体、Python 3.10 互換、単体 `.py` 配布、旧 schema 1、
  起動ガード、固定原作版、GPL と素材来歴を維持する。機能の未対応は課題として残す。

端末には有限の計算量・メモリがあるため、「任意の規模で必ず一定 FPS」を保証するものではない。
原作で扱う大規模シナリオを具体的に収集し、原作の版・規模・ルールを揃えて目標と達成状況を測る。
未達なら原因と次の実装を記録し、対象の機能や規模を小さくして合格へ変更しない。

## 現行の暫定上限を完成仕様にしない

調査対象は main `ad2124f29e79d243b9ad6f0292e4abde20ccafd4` の `src/mindusnista/app.py`。
今回これらを除去したわけではない。基準版からある制約を明示し、置換課題として管理する。

| 場所 | 現在の制約 | 解消に必要な作業 |
|---|---|---|
| `World.__init__` | 幅・高さは各 8～128 | 原作の有効範囲を調査し、タイル配列・隣接・描画・保存を大規模入力へ対応 |
| `start_wave` / `step` | 敵160以上で次ウェーブを開始せず、出現は敵200未満で進む | 原作の出現・ユニット上限ルールへ置換。探索と更新を改善し暫定上限で抑えない |
| `World.from_dict` | 読込時は敵256・弾4096まで | 旧保存を維持し、大規模な状態の検証とメモリ管理へ置換 |
| `MAX_SAVE_BYTES` | 独自 JSON 読込は8 MiBまで | 原作 codec と分離し、逐次処理と入力長検証を設計。原作セーブの仕様上限に流用しない |
| Scene の更新 | フレーム時間のクランプと1回あたり最大12 tick | 実時間・実行 tick・遅延を分けて計測。tick 数上限だけで時間予算を守れたとしない |

これは最初の監査であり全上限の棚卸し完了ではない。コンテンツ設定の範囲制限等も追加調査する。
入力破損や不正な長さを拒否する検証と、正常なゲームを小さく制限する処理は区別する。
境界値だけを削る変更は行わず、正常な大規模入力の試験と資源管理を伴って置き換える。

## 処理量を減らし、独立した仕事を並列化する

現行には背景チャンク、ノード再利用、隣接キャッシュ、共通経路探索、HUD 更新間隔がある。
ただし全建物の毎 tick 更新、弾や砲台からの全敵探索、画面外の表示更新、経路の再計算、
同期的な JSON 保存は次の測定対象。計測せず主原因や改善倍率を決めつけない。

1. 空間索引で標的・衝突の候補を限定する。画面外の描画送信を省いても世界の計算は継続する。
2. 変化がない接続や描画資源を再利用する。休止・差分更新は原作の状態遷移と一致する条件を検査する。
3. 頻繁な数値を連続配列で扱い、NumPy や既存ネイティブ関数へまとまった仕事を渡す。
4. 独立する演算を複数 CPU ワーカーへ分ける。結果の反映順・乱数・数値精度を守る。
5. エフェクトの一括描画・shader を検証し、Metal 計算も可用性と転送を含む実測で判断する。

候補ごとの根拠と未検証事項は [並列化調査](PARALLEL_RESEARCH_ja.md) に分けた。
原作共有の形式と受入条件は [セーブ共有調査](SAVE_COMPATIBILITY_RESEARCH_ja.md) を参照。

## 品質と負荷を一緒に測る

同じ配置・seed・操作・tick 数・カメラ・効果条件で、次の測定を保存する。
規模はタイル、建物、稼働搬送、ユニット、弾、接続、ロジック命令、画面内の効果数等で表す。

| 観点 | 記録するもの |
|---|---|
| シミュレーション | 実行 tick/s、tick 時間の中央値・p95・最大、積み残し時間、状態差分 |
| 操作と描画 | フレーム時間・長い停止、入力から反映までの時間、描画処理と計算の内訳 |
| メモリと保存 | ピーク使用量、コピーと割り当て、ファイル容量、保存/読込とその停止時間 |
| 持続性能 | 機種・iOS・Pythonista・電源条件、短時間と長時間の変化、発熱状態の観測方法 |
| 見た目 | 原作と同条件の画像/動画、効果の種類・寿命・色・重なり・発光・視認性 |

GPU に移しただけで合格にせず、描画の重なりによる負荷とバッファ転送も含める。
PC のカーネル測定を iPhone の FPS に換算しない。実機未測定欄は未測定のままにする。
